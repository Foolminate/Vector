## Agent Brief

### Context
We are refactoring the Seek extraction logic from `src/collector.py` into a standalone, pure module `src/parser.py`. This is part of the "Deep Modules" architectural push (PRD 6.0). Currently, extraction is scattered and hard to test without a live browser.

### What to build
1. **SeekParser (src/parser.py):**
   - A pure class `SeekParser` that takes raw content (HTML string or JSON dict) and returns structured data.
   - `parse_search_results(redux_data: dict, html: str) -> List[dict]`: Tries Redux first, falls back to DOM scraping of the HTML.
   - `parse_job_details(html: str) -> str`: Extracts the main job description text.
   - **Fix:** Properly extract `published_at` and `expiration_date` from the Redux state or DOM. Seek usually has this in the `SEEK_REDUX_DATA` under `results.jobs`.
2. **Refactor SeekCollector (src/collector.py):**
   - Use `SeekParser` inside `scrape_search_results` and `scrape_job_details`.
   - Remove extraction-heavy regex and DOM selectors from the collector.

### Implementation Notes
- **Resilience:** If Redux fails, the DOM scraper should be a robust fallback.
- **Fail-fast:** If a job title is missing, skip that job. If salary is missing, just set it to None.
- **Date Formatting:** Ensure extracted dates are converted to a standard format (ISO or similar) for the database.

### Test Strategy
- **Unit Tests:** Create `tests/test_seek_parser.py`.
- **Snapshots:** Use the existing `src/seek_page_no_results.txt` and create/mock a "results" HTML snapshot.
- **Verification:** Ensure the parser correctly handles cases with and without Redux data.
