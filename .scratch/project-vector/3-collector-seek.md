## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Implement the Playwright-based scraper for Seek.co.nz using a cascading search strategy.

**Current behavior:**
The project has a database and configuration but no way to gather job listings.

**Desired behavior:**
A `Collector` module should be implemented that uses Playwright to navigate Seek.co.nz. It must execute searches based on the `Priority 1` (Hamilton, Waikato, Remote) keywords first, then optionally expand if configured. It must extract job metadata and store it in the `jobs` table, avoiding duplicates based on the URL.

**Key interfaces:**
- **Collector Class:** Should take the `DatabaseManager` and the configuration as inputs.
- **Search Method:** Should iterate through `SEARCH_CONFIG.yaml` cascading tiers.
- **Persistence:** Should use `DatabaseManager` to insert records into the `jobs` table.

**Acceptance criteria:**
- [ ] Playwright is installed and configured for headless execution.
- [ ] Scraper extracts `job_title`, `company`, `location`, `url`, and `raw_text` (job description).
- [ ] Scraper respects the Priority 1 (Hamilton/Waikato/Remote) focus.
- [ ] Scraper implements random jitter between requests to avoid detection.
- [ ] Scraper skips jobs already present in the database (URL uniqueness).
- [ ] Integration tests verify that at least one job can be "mock" scraped or correctly parsed from a sample HTML page.

**Out of scope:**
- AI sorting or analysis of the scraped text.
- Scraping other job boards (LinkedIn, etc.).
