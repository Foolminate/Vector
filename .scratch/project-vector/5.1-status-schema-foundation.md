# Issue: Status Schema Foundation

## What to build
Implement the foundational database and logic changes required for granular status tracking and decision-maker attribution. This includes applying the schema migration and updating the Sorter and Evaluator modules.

## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Update the database schema and core logic to support granular job status tracking, decision attribution (robot vs human), and expiration dates.

**Current behavior:**
The `jobs` table lacks fields for tracking when a job was last checked for validity, who made the last decision (Agent 1/2 vs User), and when a listing is expected to expire. `Sorter` and `Evaluator` do not record the decision source.

**Desired behavior:**
- The database should include `last_checked_at`, `is_valid`, `last_decision_by`, and `expiration_date` columns.
- `SeekCollector` should set a default 30-day expiration date upon discovery.
- `TriageSorter` and `JobEvaluator` should set `last_decision_by = 'robot'` when updating status.
- The system should be prepared for the TUI to distinguish between automated and manual decisions.

**Key interfaces:**
- **Database Migration:** Apply `migrations/v7_add_validity_and_granular_status.sql` (if exists) or create it.
- **`src/collector.py`:** Update `save_job` logic.
- **`src/sorter.py`:** Update `update_job_status`.
- **`src/evaluator.py`:** Update `save_evaluation`.

**Acceptance criteria:**
- [ ] Database migration applied adding `last_checked_at`, `is_valid`, `last_decision_by`, and `expiration_date`.
- [ ] `TriageSorter.update_job_status` sets `last_decision_by = 'robot'`.
- [ ] `JobEvaluator.save_evaluation` supports `shortlisted` and `discarded` verdicts and sets `last_decision_by = 'robot'`.
- [ ] `SeekCollector.save_job` assigns a default 30-day `expiration_date`.

**Blocked by:**
None - can start immediately
